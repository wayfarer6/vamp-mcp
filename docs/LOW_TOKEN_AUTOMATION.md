# 반복 GUI 자동화의 토큰 사용 원칙

저장된 RPA의 동작과 결과 검증을 로컬에서 수행하고, LLM에는 판단에 필요한 짧은 결과만 전달합니다. OCR·YOLO를 쓴다는 사실만으로 토큰이 자동 절감되지는 않습니다. 인식 결과 전문과 이미지를 다시 LLM에 계속 보내면 입력 토큰이나 멀티모달 비용이 발생합니다.

- 정상 실행: `status`, `verification`, 필요할 때 짧은 `error_summary`, 증거 파일 경로와 식별자만 읽습니다. 로컬 파일 존재·내용·해시 등 작업별 성공 조건은 유지합니다.
- 추가 확인: 실패·모호한 판정·UI 변화·사용자가 요청한 검토가 있을 때 검색어, 페이지, 화면 영역을 좁혀 OCR·YOLO 근거를 읽습니다. 필요한 경우에만 스크린샷을 모델에 전달합니다.
- 기본 제외: OCR 전문, YOLO 전체 박스 배열, 이미지 Base64, 전체 Robot 로그·소스, 변화 없는 화면의 반복 업로드. 자동화 코드가 로컬에서 이 파일을 읽거나 영상을 녹화하는 것은 LLM 문맥에 넣는 것과 다릅니다.
- 절감 범위: 정상 RPA 재생에 LLM API 호출이 없어도 에이전트가 MCP 도구를 선택하고 결과를 읽는 토큰과 VM·로컬 모델·전력·실행 시간·처음 작성 및 UI 보정 비용은 남습니다. 비교 측정 전에는 절감률을 단정하지 않습니다.

`vm_inspect`와 `vm_read_evidence`는 `query`, `offset`, `limit`를 이용해 필요한 부분만 읽습니다. 원격 캡처에서 해상도나 저장 경로만 필요하면 `remote_vm_screenshot(include_image=false)`를 사용합니다. RPA의 `completed_unverified`는 입력 전달 완료이므로 실제 업무 성공 검증을 생략하는 근거로 쓰지 않습니다.

## 새 GUI RPA를 작성할 때

AI가 RPA를 구현하거나 보정할 때는 다음 로컬 검증을 기본으로 코드에 넣습니다.

1. 업무의 실제 완료 조건을 정합니다. 예: 인쇄 저장 대화상자, 클릭 후 변경된 문구, 만들어진 PDF의 송장 번호·합계.
2. Python `workflow.py`에 OCR 또는 YOLO 기반 검사 함수를 작성합니다. OCR은 텍스트·상태, YOLO는 필요한 UI 영역 후보를 확인하고, 박스 하나가 잡힌 사실만으로 완료 처리하지 않습니다. 파일을 만드는 작업에는 존재·내용·해시 등의 검사도 추가합니다.
3. Robot 작업에서 검사 함수를 호출하고 긍정적인 결과를 assert합니다. 제한 시간 안에 기대 상태가 없거나 모호하면 실패 또는 미검증 상태로 반환합니다. 검증이 없는 빈 템플릿은 `not_configured`로 유지합니다.
4. 실제 VM에서 정상 결과와 기대 조건 불일치를 확인하고, 반복 실행에서도 검증을 유지합니다. 정상 실행은 모델에 이미지나 OCR 전문을 보낼 필요 없이 짧은 결과만 반환합니다.

작업의 기대 결과를 모르는 scaffold/정적 변환기가 검증을 추측해 성공을 선언하게 만들지는 않습니다. AI 또는 사람이 작업을 구현하는 단계에서 의미 있는 검증을 추가해야 합니다. [PDF 예제](../rpas/windows_print_pdf/workflow.py)는 프린터 OCR과 실제 PDF 내용·제작자·해시를, [원격 입력 예제](../rpas/remote_host_validation/run.robot)는 버튼 클릭 전후 문구를 검사합니다.
